# Архитектура Warehouse

Warehouse работает локально: Electron обслуживает окно и SQLite, Vue отображает
интерфейс. Сетевого сервера и предметных складских модулей пока нет.

## Поток данных

```text
Компонент Vue → Pinia → renderer service → desktopAPI
  → preload → IPC handler → main service/repository → SQLite
```

Компоненты отвечают за отображение и действия пользователя. Store хранит состояние
экрана, ожидание и ошибки. Renderer service обращается к ограниченному bridge;
бизнес-логика и работа с базой остаются в main.

## Границы

`src/main` содержит запуск, создание окна, обработчики IPC, сервисы, репозитории
и миграции. `src/renderer` содержит layouts, views, components, stores, composables,
services, infrastructure и стили. В `src/shared` находятся общие каналы, контракт
bridge и валидация настроек. Статические ресурсы лежат в `src/public`.

Renderer работает с `contextIsolation` и sandbox, без Node.js. Preload открывает
только конкретные операции `desktopAPI`; произвольный IPC, SQL и файловые пути
не являются клиентским API. Main проверяет отправителя и входные данные.
Внешняя навигация, новые окна, webview и разрешения браузера блокируются.
Для собранного интерфейса применяется CSP. Подробности ошибок остаются в main,
пользователь получает безопасное сообщение.

## Хранение

Единственная база создаётся в `app.getPath('userData')/data/warehouse.sqlite`.
Идентичность приложения и каталог данных независимы от Work Board.
`app_settings` хранит тему; `PRAGMA user_version` задаёт версию схемы.
Миграции транзакционные, включены foreign keys, WAL и busy timeout.
Соединение закрывается при выходе. Некорректная или более новая схема
не перезаписывается. Предметных таблиц заранее нет.

## Добавление функций

Новый складской сценарий добавляйте вертикально: страница и store, renderer
service, узкая операция bridge, IPC handler, main service и repository.
Входные данные проверяйте на границе main, изменения схемы оформляйте миграцией.
Для новой операции проверяйте бизнес-результат, ошибки и ограничения IPC.
Компонент не должен обращаться к SQLite напрямую.

## Сборка и проверка

Vite создаёт `build/renderer` и `build/main/preload.cjs`; Electron запускает
main отдельно. Режим разработки использует `127.0.0.1:5174`.
Обёртка запуска убирает `ELECTRON_RUN_AS_NODE` перед запуском Electron;
`WAREHOUSE_DEVTOOLS=1` включает инструменты разработчика.

Автоматические проверки охватывают настройки, миграции, повторное открытие базы
и границы IPC/bridge. Desktop-проверка использует настоящий Electron и отдельный
каталог userData. Упаковка Windows создаёт unpacked, NSIS и portable в `release`.
Зависимости, сборки, runtime-данные и рабочие планы агентов не входят в Git.
